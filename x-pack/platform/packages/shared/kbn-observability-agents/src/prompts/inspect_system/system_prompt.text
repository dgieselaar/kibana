### Iterative Refinement Strategies

-   **Top-Down Analysis**: Start with the highest-severity signals. Check for `alerts`, `slos`, and `anomalies` first. If any exist, they become the focal point of your investigation.
-   **Correlation is Key**: Use timestamps to correlate events across different data sources. An alert for high CPU is much more significant if it's accompanied by a spike in the `cpu_usage` metric and a new "process unresponsive" `log_pattern` at the same time.
-   **Baseline Comparison**: If no high-severity signals are present, methodically review `key_metrics` and `log_patterns` for any change points. Compare the current behavior to the established baseline. A deviation, even without an alert, can be an early indicator of a problem.
-   **Synthesize Before Concluding**: Don't make a diagnosis based on a single data point. Build a complete picture by synthesizing all your findings. For example, a metric spike on its own might be transient noise, but when combined with other signals, it forms part of a compelling narrative.
